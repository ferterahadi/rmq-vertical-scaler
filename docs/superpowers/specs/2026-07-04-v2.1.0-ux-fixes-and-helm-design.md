# v2.1.0 — Install/config UX fixes + Helm chart

Approved 2026-07-04. Scope: the "quick-fix pack" (A) and an in-repo Helm chart (B)
from the install/configure UX audit. Release version **2.1.0** on branch
`release/2.1.0`.

## Motivation (audit findings)

- `generate` accepts broken configs silently: typo'd keys are ignored, profiles
  missing `cpu`/`memory` emit `value: ''` which the runtime silently replaces
  with defaults the user never chose. Exit 0, "✅ Generated". The JSON schema in
  `schema/config-schema.json` exists but the CLI never checks it.
- Default image is `:latest` with `imagePullPolicy: Always` — non-reproducible
  deploys; a future major push mutates existing deployments on pod restart.
- Quick Start requires a repo clone (`--config examples/...`) that `go install`
  and release-binary users don't have; the curl-able template's
  `"$schema": "../schema/config-schema.json"` is dead outside the repo.
- Installing the scaler silently creates a PDB targeting the **RabbitMQ** pods,
  hardcoded `minAvailable: 2`, with a comment that misdescribes it. No opt-out.
- Secret contract (`{serviceName}-default-user`, keys `username`/`password`) is
  hardcoded — anyone not using the RabbitMQ Cluster Operator must reshape their
  secret.
- No ecosystem-standard install path (Helm).

## A1 — Config validation in `generate`

- Embed `schema/config-schema.json` in the binary (`go:embed`); validate the
  `--config` JSON against it using `github.com/santhosh-tekuri/jsonschema/v6`
  (pure Go). The schema file stays the single source of truth — no
  hand-duplicated rules.
- Tighten the schema: `additionalProperties: false` at every object level (so
  `debounse` is an error), require `cpu` + `memory` per profile. The legacy
  top-level `thresholds` block remains valid.
- Validation failure = non-zero exit listing **every** violation with its JSON
  path. No `--no-validate` escape hatch.

## A2 — Pinned default image tag

- Default image becomes `ferterahadi/rmq-vertical-scaler:<version>`.
- Version resolution order: ldflags (`main.version`) →
  `runtime/debug.ReadBuildInfo` module version (covers `go install`) →
  fallback `:2`. Never `:dev`, never `:latest`.
- `imagePullPolicy: Always` stays (safe for both pinned and user-supplied
  mutable tags; minimal diff).
- Golden/parity tests updated; README's "byte-for-byte v1 manifests" claim
  softened to note the pinned default tag.

## A3 — Absolute `$schema` URL

All example configs and the `init` scaffold use
`https://raw.githubusercontent.com/ferterahadi/rmq-vertical-scaler/master/schema/config-schema.json`
so IDE validation works outside a repo checkout.

## A4 — `init` subcommand

- `rmq-vertical-scaler init [-o my-config.json]` writes the embedded template
  config (default filename `my-config.json`), **refuses to overwrite** an
  existing file, and prints next steps (edit → `generate` → `kubectl apply`).
- README Quick Start becomes `init` → `generate` — no repo clone needed for any
  install method.

## A5 — PDB opt-out

- New `generate --no-pdb` flag skips the PDB document. Flag-only for this
  release (no config field).
- Template comment corrected: the PDB protects the **RabbitMQ** nodes during
  scaling restarts and assumes a 3+ node cluster. `minAvailable: 2` unchanged.

## B — Helm chart (in-repo only)

`charts/rmq-vertical-scaler/`, chart `version` = `appVersion` = `2.1.0`.

- **values.yaml**: image (repository/tag/pullPolicy), `serviceName`, rmq
  host/port overrides, **secret name + username/password key overrides** (fixes
  the hardcoded secret contract), `profiles` as an **ordered list**
  (`[{name, cpu, memory, queue, rate}]` — a YAML map would lose the floor-first
  ordering that drives profile selection), `debounce`, `checkInterval`,
  `pdb.enabled` + `pdb.minAvailable`, scaler container resources, `rbac.create`,
  `serviceAccount.create`/`name`.
- Templates mirror the generator's manifests (ServiceAccount, Role,
  RoleBinding, state ConfigMap, conditional PDB, Deployment). Namespace comes
  from `.Release.Namespace` — no hardcoded namespace metadata.
- `values.schema.json` for helm-native validation; `NOTES.txt` prints rollout +
  logs verification commands; chart README with values table.
- Install docs: `helm install` from a git checkout or GitHub tarball URL.
  Registry publishing (gh-pages / OCI) deferred to a follow-up.
- CI: `helm lint` + `helm template` smoke step in the workflow.
