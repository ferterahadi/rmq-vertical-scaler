# Acceptance evidence bundle

Git keeps a [concise acceptance summary](../tests/e2e-v2/acceptance-summary.json)
and the [human-readable results](v2.3-acceptance-results.md). The 713 raw acceptance
and feasibility captures are packaged as one deterministic archive, outside the
tracked source tree. Both `tests/e2e-v2/results/` and `tests/feasibility/results/`
are ignored; existing local captures are preserved.

## Reproduce and verify

From a clone with the recorded evidence commit available:

```bash
# Fetch history first if this is a shallow clone.
git fetch --unshallow
# In a full clone, skip that command.
python3 scripts/package-v23-evidence.py
python3 scripts/check-v23-release-evidence.py v2.3.0
```

The archive is written to
`dist/acceptance/2.3.0/rmq-v23-evidence.tar.gz` (1,749,907 bytes), SHA-256:

```text
a2b3d0d18b105b7bd000a16dd23bc5e52efa2a1e0844f49265eb6d73c4652b35
```

The source commit is `44e4a1a3e088c53966f7c5e085ffe6080cb1a7a1`.
Ordering, gzip headers and tar metadata are fixed, so independent reconstruction
produces identical bytes. No untracked files or live credentials are included.
This change removes bulk captures from the current tree and PR file diff, not
from historical storage. **Merge this PR with a merge commit, not squash/rebase,**
while reconstruction depends on Git history. The packager rejects checkouts that
no longer contain the source commit. PR CI cannot enforce the later merge method;
maintainers must preserve that ancestry until independent bundle retrieval is
available. A separately retained bundle can still be verified
with `--bundle /path/to/archive.tar.gz` without that history. Missing history and
a missing bundle block a release.

The PR workflow reproduces and verifies the archive, then stores that single
approved archive as a GitHub Actions artifact. The release workflow reconstructs
and verifies before any 2.3 publication. A missing/corrupt archive, altered capture,
wrong image, changed controller input or failed acceptance requirement blocks
verification. No production release is performed by the evidence workflow.

## Download the retained artifact

Open a successful [Acceptance evidence bundle run](https://github.com/ferterahadi/rmq-vertical-scaler/actions/workflows/acceptance-evidence.yml)
and download its `rmq-v23-evidence` artifact, or use the run ID from the PR:

```bash
gh run download RUN_ID --repo ferterahadi/rmq-vertical-scaler \
  --name rmq-v23-evidence --dir dist/acceptance/2.3.0
python3 scripts/check-v23-release-evidence.py v2.3.0
```

Storage is retained for **90 days**. Each successful run produces an immutable
artifact ID; later runs do not overwrite it. The checksum above identifies the
inner `.tar.gz`, not GitHub's transport ZIP. The gate verifies the downloaded
archive before reading the original captures. Keep an independent copy before
retention expires, or preserve the source history for reconstruction. The
release workflow still reconstructs from Git, so its merge-commit requirement
remains in effect.

## Browsing captures

The verifier safely extracts into a temporary directory, then checks all original
source/image, message-accounting, runtime and timing requirements. To inspect
captures locally, verify first and then extract:

```bash
python3 scripts/check-v23-release-evidence.py v2.3.0
tar -xzf dist/acceptance/2.3.0/rmq-v23-evidence.tar.gz
```

Original paths remain inside the archive, including:

- `tests/e2e-v2/results/acceptance.json`: original fingerprint manifest.
- `tests/e2e-v2/results/full-acceptance.json`: detailed 31-requirement evidence map.
- `tests/e2e-v2/results/final-acceptance-2026-10-30/`: final build and eight runtime groups.
- `tests/e2e-v2/results/rolling-latency-diagnostics-2026-10-30/`: retained timing failures and tuning proof.
- `tests/feasibility/results/`: broker-budget feasibility evidence.

## Source provenance after packaging

The original captures and their source fingerprints remain byte-for-byte
unchanged. Six packaging/verification files are separately fingerprinted in the
tracked summary. This narrow amendment covers the archive tooling, its tests and
workflows; controller, policy, schema, chart and other tested inputs must still
match the original acceptance snapshot. Packaging tests and CI validate these
new files separately. The accepted controller image is unchanged.

The packaging change passed all 45 harness/gate regressions, including twelve new
archive tests. The original 33-test result remains unchanged in the bundle.
